## 医生流程和事实边界

登录后，从其他工作入口进入 `/followup-plans`。默认今天，支持未来 7 天（今天至第 6 天）、早于今天、自定义含端点日期及全部日期；可筛选已核对或需重新核对。查看病例身份、计划日期、目的、版本，展开原文，打开该病例准确计划版本。创建、更正、撤销沿用原 CW-B14 核对保存流程。

仅包含当前账号拥有的未删除病例，每病例只呈现当前未撤销计划。更正历史和撤销版本保留在原面板；过期或缺失定位明确显示，不替换为另一个计划。早于今天不代表未实际复查、风险或联系结果。空清单不等于无需复查。未新增预约、提醒、完成登记、分派、AI 建议、签署和旧回访 KPI 变化。

## 只读接口和一致性

`GET /api/followup-plan-queue` 使用真实 JWT；不接受 owner 参数或重复参数。`range=today|next7|past|custom|all`、`state=all|planned|needs_review`、`page=1..1000000`、`page_size=1..50`（默认 20）、`snapshot`（64 位内容快照）。custom 必须给真实日历 `start/end`，起点不晚于终点；其他日期模式不接受这两项。连续翻页必须携带快照。

协议 `clinical-followup-plan-queue-cw-b18-v1` 返回上海日期、UTC 读取时间、实际筛选、总数、页码、最小身份及当前计划原文/版本来源、快照和上限。不附电话或完整病例正文。病例定位 URL 仅携带病例 ID、计划 ID、版本，不携带原文、凭据或快照。成功、校验错误、认证失败和服务错误均 `Cache-Control: private, no-store`。

开关 `FOLLOWUP_PLAN_QUEUE_ENABLED=1` 与 `FOLLOWUP_PLAN_QUEUE_SYNTHETIC_ONLY=1` 默认关闭，只允许 test/development、非 Render；同受 CW-B14 计划开关约束。禁用时不查询计划。未登录前端不请求受保护接口。

PostgreSQL 使用独立 Session、REPEATABLE READ、READ ONLY；SQLite 显式 BEGIN。先按账号/未删除/计划 namespace 获取最多 201 个病例，再批量获取最多 10001 条计划行；业务 SELECT 最多 2 次，另有 JWT 用户查询，无逐病例查询。namespace 仍为状态前缀或 channel 来源的 OR 定义，旧式随访不混入。抽取 CW-B14 的完整纯版本链校验，既有 `records` 委托执行，无规则放宽或旧写入变化。

所有相关病例与链先完整校验，再按原计划日期、病例 ID、计划 ID 排序，筛选及分页。最多 200 病例、10000 版本行，每病例最多 50 版；超限和损坏明确失败，不截断或修复。快照包含账号、上海日期、筛选/页大小、相关病例资料与全部计划版本内容指纹；变更拒绝旧快照。GET 不写业务表、审计或附件，不清理文件，不生成文书。

## 页面失效与回看

延迟加载第 7 个次级路由；初始 JS≤460000 字节，每 chunk≤500000 字节。登录变更、筛选、刷新、分页、失焦/返回、可见性和跨日会清除旧列表的有效状态；AbortController 与请求序号拦截迟到回包。快照冲突重读第 1 页，失败保留筛选，重试只发 GET。不持久化临床清单。
