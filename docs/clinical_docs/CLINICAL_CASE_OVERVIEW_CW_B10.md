## 医生流程与字段含义

1. 打开已保存病例，点击“打开就诊资料总览”。只显示服务器已保存记录；未保存草稿不参与。
2. 查看病例编号、动物和宠主身份，以及主诉、病史、查体、评估、诊疗计划、预后与补充说明。文本仅区分有记录、未填写、未知结构；可展开完整已保存原文。评估文字不等于已确认诊断，不解释数值或否定词。
3. 按原件、检验、影像查看当前有效、需重新核对、来源不可用、旧版本、已撤销。检验和影像按报告根去重，只把当前有效版本计入“当前已核对”；更正历史另列。原件名、完整 SHA-256、核对账号/时间和原因可追溯。
4. 提示仅包括未填写字段、无对应人工记录的原件、需重核或来源不可用及旧式资料限制。不要求必须开展某检查，不评分，不宣称病例完整。
5. 导航打开现有检查资料、检验、影像面板，保留已打开面板的草稿。病例编辑在新标签页打开，返回后焦点事件重新读取。两类文书仍走既有完整核对入口，不自动选择、确认或下载。
6. 查看读取时间；总览是该次读取的快照。保存、更正、撤销、来源变化、病例/账号切换、焦点返回及手动刷新使旧结果失效。失败时不继续显示旧结果。

| 总览标签 | 已保存字段 | 含义 |
| --- | --- | --- |
| 主诉 | `chief_complaint` | 完整已保存原文 |
| 病史 | `history` | 完整已保存原文，含换行、否定词和特殊字符 |
| 查体记录 | `exam_findings` | 原字段有无，不自动解释内部文本 |
| 评估内容 | `analysis` | 有记录不代表医生确认诊断 |
| 诊疗计划 | `treatment` | 已保存计划，不生成新建议 |
| 预后与补充说明 | `prognosis` | 既有共用字段；不虚构另一个独立补充说明字段 |

## 只读性、一致性与限制

鉴权 GET `/api/cases/{case_id}/visit-overview` 仅按病例 ID 和当前账号查询，拒绝越权及软删除病例。响应明确 `read_only=true`、`writes_database=false`、`includes_unsaved_drafts=false`，并发送 `Cache-Control: private, no-store`。快照哈希绑定本次返回的身份、字段、来源、版本与限制，不包含每次变化的读取时间。

复用已有 Store 锁及病例事务，持有至完整结果组装完成：SQLite 用独立 `BEGIN IMMEDIATE`，PostgreSQL 用病例行锁。来源读取直接校验原件字节，不调用会清理暂存资料的附件 `listing`。不提交事务，不新增/更改病例、报告、审计、原件或暂存业务文件；锁文件和目录等同步设施不属于业务原件。

模块未启用返回 `disabled` 及未知数量，不当成空记录。旧式附件和旧流程报告单独计数并提示回原入口核对；不假冒 CW 原件。未知来源结构、报告结构、非法版本链、身份结构或损坏的数据返回明确失败。原件丢失/损坏/撤销不计为有效来源，身份或元数据变化需重核。

默认关闭。仅 `ENVIRONMENT=test/development`、`RENDER=false`、既有原件开关及 `VISIT_OVERVIEW_ENABLED=1`、`VISIT_OVERVIEW_SYNTHETIC_ONLY=1` 同时满足时开放；检验、影像分别沿用其原开关。生产及 Render 拒绝。前端按需加载。无新表、迁移、依赖、锁文件、模板二进制、基础设施、OCR、设备连接或业务外部服务。
