## 目标与实现

此前结构化答案只进入当轮 AI 上下文，未随会话 answers 保存；下一轮及刷新后丢失，首次保存又依赖前端最后一份内存快照。本次修复既有数据保留链路，不新增医学问题或诊疗解释。

- 复用 ConsultSession.answers 现有 JSON 列，在普通 question/answer 项内加入 JSON 字符串 `structured_intake_snapshot`，保持既有字符串字典响应兼容。保留模板键/版本、分组/问题键及标签、答案原文和来源轮次；不改模型或数据库结构。
- 类型、未知字段、数量和长度在 AI 调用/写入前校验。最多 60 组、每组 200 项、合计 600 项；单项原文 100,000 字符，元数据 1,000 字符，单快照序列化 250,000 字符，会话快照累计 1,000,000 字符。超限返回 422；损坏的既存快照阻止继续保存，不静默丢弃。
- 后续上下文读取所有已保留快照；保存前预览、首次保存、明确选择 consult_sync 的更新包含这些原文。history_only 仍只追加医生补记，不偷偷同步新问诊内容。
- 原文不 trim、不把空白转换为“无异常”。轮次/版本和原文结束标记位于答案之外；否定词、换行、Unicode、字面 HTML 保留并作为文本显示。完整来源块重复附加被抑制，不合并不同轮次的相同答案。第三轮更正保留前两轮。
- GET/成功响应显示已提交记录，待提交输入独立；请求绑定当前会话和账号，迟到响应不应用到另一会话/账号。提交锁抑制双击；结果不确定时保留输入并只允许 GET 核对，不自动再次 POST。
- 可选 `expected_answers_token` 绑定原答案序列；旧轮次重放在 AI 调用前返回 409。PostgreSQL 行锁与条件更新防止覆盖竞争写入。旧客户端不传令牌仍可用；不声称所有旧客户端或跨客户端操作具有幂等性。
- 旧会话没有快照时照常读写，不反推或回填已经丢失的答案。兼容旧客户端保存时再次携带最新快照，避免同一回执重复附加。
- 文书复用已有核对/导出路径与原模板，导出最终已保存的病例原文；仍是待医生核对、未签署草稿。
