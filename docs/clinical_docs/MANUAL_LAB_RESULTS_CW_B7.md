## 操作与数据约定

已保存病例打开“检验项目”，选取已核对关联的检验 PDF/JPEG/PNG。医生手工抄录标题、报告类型、样本、带时区的时间、实验室、仪器及备注。每行填写项目、原文值、结果类型、单位、范围原文、可选范围上下限及其单位、原报告标记和页码/定位说明。逐项核对后，预览病例身份、原件和整份报告，再确认保存。

结果类型独立区分数值、比较值、文本、未测、未提供。原文逐字保留；数值只生成 Decimal 字符串，不写二进制浮点权威值。不做单位换算、范围推断、异常判定或医学解释。范围数值可留空；填写时必须带原文，单位与结果完全一致且下限不大于上限。每份 1–100 项、每病例最多 20 个未撤销报告根、每根最多 20 版本；达到上限仍可查看和撤销。

本页草稿只存内存，离开/刷新提示；账号或病例切换清除。草稿编辑使核对失效。保存结果不明时先 GET 请求结果，只在明确未提交后允许重新核对，不自动补发 POST。原件通过现有带鉴权接口下载并验证长度/SHA-256，不生成公共链接。

## 持久化与隔离

复用现有 `DiagnosticReport`、`Observation`、`AuditLog`，source_type 固定为 `manual-lab-cw-b7`，metadata schema 为 `manual-lab-cw-b7-v1`，不改模型、迁移或数据库结构。确认把报告、逐项数据与审计写入同一事务。更正新建版本并保留旧值，更正/撤销必填原因。审计操作者来自当前鉴权账号。

沿用原件存储锁，再取病例行锁；SQLite 使用 BEGIN IMMEDIATE，PostgreSQL 使用 FOR UPDATE。原件更正/撤销与关联检验状态失效同事务；病例姓名、物种、性别、品种、毛色、宠主变更同事务使确认失效。读取与确认仍复核原件字节、来源快照、病例身份和报告版本。原件不可读、损坏或关联变化时不会返回当前有效确认；保留历史供核对或撤销。单纯病史补记不改检验值。

同一病例/原件只有一个报告根；补充项目走更正，撤销后的原件记录保留历史，不能用重复创建覆盖。重复请求以账号、病例和 request_id 绑定，内容不同拒绝；成功请求再次回读返回记录当前状态，避免旧“成功”恢复已撤销状态。

CW-B7 数据只用于专用人工页面。旧诊断列表/汇总、文书合并读取不包含新数据；旧报告确认、AI 摘要、异常标记和摘要审计写入不能修改 CW-B7 对象。原有其他来源保持原行为。两类文书、病史、诊断和治疗内容不自动吸收此次录入。
