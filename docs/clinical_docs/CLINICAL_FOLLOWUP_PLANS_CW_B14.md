## 医生流程

病例详情按需打开复查计划，医生填写日期、目的、1–10 个项目、提前返回条件及备注。读取当前病例与完整版本历史，先预览原文、原版本和病例身份，再单独勾选核对并保存。计划不代表已经复查；没有计划不代表无需复查。过去日期仅提示核对，不自动调整。

更正追加新版本；撤销保留最后版本原文与原因、账号、时间。最多 1 份当前计划、每病例最多 50 条版本，达到上限仍可撤销。正文或身份变化使当前计划显示“待重新核对”；读取不改写计划或审计。草稿仅存在当前页面内存，关闭与离开提示；原有检验、影像、文书及病例编辑输入保留。

本批不生成临床建议、不抽取处理或风险原文，不预约、不发送消息、不关联其他病例。计划尚未进入 DOCX，现有门诊复查占位提示不变。

## 数据、事务与协议

复用 FollowUp、AuditLog，无模型变更或迁移。`note` 保存 `clinical-followup-plans-cw-b14-v1` 结构，`channel=clinical-followup-plans-cw-b14` 仅标识本批来源，状态限定 `cw-b14-planned/superseded/withdrawn`，`done_at` 始终为空。所有状态前缀或来源标记匹配本批的记录，包括损坏样本，均从旧 KPI 排除；既有自由文本回访记录不转换。

`planned_date` 保留上海公历日期，`due_date` 是上海午夜对应 UTC-naive；操作时间记录带 UTC 时区的 ISO 时间戳。日期列和原文字段必须一致；服务器时区不影响显示。目的与可选条件/备注最多各 1000 个 Unicode 码点，项目每项最多 300，原因最多 500；拒绝空必填、超限、非法日期、未知字段和控制字符，不截断、不规范化或重写空白。

接口 `/api/cases/{case_id}/followup-plan`：GET 完整读取、POST `/preview`、POST `/confirm`、GET `/requests/{request_id}`。真实 JWT 验证归属及软删除。成功响应和服务错误为 private/no-store。401 未认证；404 不可访问；409 快照变化/损坏/冲突；422 输入或上限错误；503 关闭或数据库故障。

SQLite 独立 BEGIN IMMEDIATE；PostgreSQL 同归属 Case FOR UPDATE。计划和一条审计同事务提交。读取/预览/请求结果核对不写业务表。确认绑定病例身份正文、完整计划状态、本次内容、日期和预览 token。幂等范围为账号+病例+来源+请求 ID；相同指纹重放返回已提交结果且 `writes_database=false`，换内容冲突。

确认开始即锁定写操作。丢失回包先按原请求 ID 核对，再独立读取计划；不可确认时保留草稿并提示继续核对，不自动重发。未查到已提交不是取消写事务的承诺；同 ID 的再次明确确认仍受幂等保护。组件刷新、焦点返回、字段变化、病例更正请求、病例/账号切换会作废预览并丢弃迟到回包；中断前端请求不承诺取消已发出的保存。

默认关闭 `FOLLOWUP_PLANS_ENABLED`、`FOLLOWUP_PLANS_SYNTHETIC_ONLY`；只有两者均为 1、test/development 且非 Render 时可用。不依赖附件开关，不加入依赖、锁文件、模板二进制或基础设施。
