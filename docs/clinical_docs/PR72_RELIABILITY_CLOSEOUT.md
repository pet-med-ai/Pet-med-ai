# PR #72 首院合成试用候选：有限可靠性验收

本批由 2026-10-19 的可靠性收口请求触发。起点为集成分支提交 `b63bcae0e80637dcad15ef0eab9a53eaf6815826`，代码树 `400c3d9fbfa09f04b13580060e0f0dc6ad2f5e05`。最终候选提交、代码树、首次自动 CI 和实际证据以本批回执为准。

范围限于本机、单医生账号、合成犬猫、临时 SQLite，以及隔离 PostgreSQL 自动验收。维持草稿 PR；不合并、不部署、不迁移、不操作生产数据，不替换已验收的 Mac 冻结副本。旧版 `586b21f5f9ebfb7531db9d8d2807ddee57fbab1c` 的 Mac/Word 回执保留，但不证明本次修复通过。

## 已处理的可靠性缺口

1. 复查计划、人工随访保存结果未知时，在发送确认请求前，写入并回读当前标签页的恢复标识。标识按练习会话、API 地址、账号、病例和记录类型隔离，仅保存请求/版本标识与内容 SHA256；不缓存临床正文或登录凭据。存储不可写、无法回读或格式异常时，阻止新保存。
2. 刷新或同账号重新登录后恢复待核对状态。主动查询原请求后，必须再独立读取版本列表，并核对原文摘要、版本、操作和归属，才能解除待核对状态。只读查询不自动重发保存；晚到的旧账号响应不被新页面接受。`not_committed` 仅表示查询时没有该请求的已提交回执，还需独立回读和人工重新预览。
3. 复查计划每个新增/更正版本必须恰有一份相符审计，撤销必须另有撤销审计。核对请求绑定、病例、版本、操作、操作者、原因及时间。缺失、重复、孤立或不匹配时返回错误；不能被解释为空列表或“未保存”。读取、预览、确认、请求查询、文书、概览和队列共用此检查。
4. 队列额外预取审计，查询次数不随病例数增长；审计变化使翻页快照失效。保留每病例 50 版本、200 病例/10000 版本上限。读取无数据库写入，也不自动修补审计。

## 保障及边界

| 项目 | 有限保障 | 不覆盖的情况 |
| --- | --- | --- |
| 写入与审计 | 同事务落盘；注入失败时整体回滚；同请求重放不增添第二份记录或审计 | 不构成生产备份、容灾或防篡改认证 |
| 未知结果 | 同一标签页刷新、同账号重新登录后，可用原标识查询与独立回读；不会自动重发 | 关闭标签页、清除存储或更换设备后的自动恢复；未保存正文恢复 |
| 关键审计 | 完整性、数量、归属和操作一致性校验；异常阻止继续确认 | 不能识别数据库管理员协同改写全部业务及审计字段；原 CW-B14 审计未保存完整请求正文，不能由 fingerprint 重建请求 |
| 文书回执 | 指向明确的未签署草稿、选择的保存版本及内容标识；生成文件仍需核对 | 内容 SHA256 不是医生签名；下载事件不证明 Word 排版完成核对 |
| 练习退出 | 正常退出回执绑定候选和源码，记录子进程停止及临时数据清理 | 断电/SIGKILL 的清理；启动回执不代表所有操作验收通过 |
| Mac 证据 | 新候选独立副本上运行，记录实际 darwin 平台和精确提交 | Linux/Chromium/CI 通过不能代替 Safari/Word 实测 |

异常处理：保留请求标识及脱敏错误回执，停止该项写入，先核对记录；不得通过删存储、改数据库、清理审计、重复点击来制造成功。原文与记录都无从核实时，结论保持“结果未知”。

## Mac 定向复验

在独立候选副本和已准备好的依赖中，用最终回执里的完整 SHA 执行：

```bash
python3 scripts/verify_candidate_reliability_mac.py --expect-head <本批完整候选SHA> --out <源码目录外尚不存在的回执目录>
```

若原冻结副本已有虚拟环境，可使用其 Python 的绝对路径，无需改写冻结源码。脚本只接受 macOS、精确提交和干净源码；不安装、不拉取、不升级。失败即停。成功状态特意为 `AUTOMATED_CHECKS_PASSED_GUI_PENDING`，不能据此填 Safari/Word 通过。保存 `receipt.json` 及对应日志。

随后在同一独立候选中，以空闲的独立端口启动练习：

```bash
python3 scripts/run_clinical_doctor_trial_cw_b26.py --expect-head <本批完整候选SHA> --ui-port 5175 --api-port 18028 --receipt <尚不存在的停止回执.json>
```

仅用本轮合成账号/病例。在 Safari 中定向核对下列项目，异常时保留截图及操作步骤，不继续下一项：

| 项目 | 通过证据 |
| --- | --- |
| 病例首次读取失败/账号变化 | 旧账号响应不会显示为新账号病例；错误后有明确反馈，重新登录后可主动重新读取，不持续转圈 |
| 编辑复核与整份草稿 | 窗口往返或账号变化后，旧确认失效并有反馈；主动重新读取后才能重新确认；不自动保存或下载 |
| 未知结果恢复 | CI 浏览器用例覆盖真实请求丢回复、刷新、重新登录；Safari 若遇到该状态，显示同一请求标识，主动只读核对后版本数不重复。未发生时记“未实测”，不能填通过 |
| 两类 DOCX | 门诊及宠主草稿都明确纳入所选检验/影像/复查/随访；确认后各下载一次；Mac Word 核对原文、换行、特殊字符和分页。记录文件 SHA256/大小和页数 |
| 正常退出 | Ctrl+C 后 `STOPPED`、`children_stopped:true`、`temporary_data_removed:true`，候选 SHA 和源码摘要与启动一致 |

若要有确定的 Safari 丢回包故障注入证据，需另设受控测试，不要求医生通过断网猜测是否已写入。人工截图及现象记录不写入账号密码或 token。若任一项不能完成，保留为未验证，不复制旧 Mac 验收结果。

## 结论规则

只有候选绑定一致、本地定向回归和首次自动 CI 通过、Mac 定向实测证据齐全，才可写“本机合成试用有限范围通过”。Mac 证据未取得时，仅能写“代码可靠性定向检查通过，Mac 验收未闭合”。这不授权真实病例录入、正式签署、生产使用、合并或部署。
